QUICK NOTE ON v3.3.4 - MULTI-PRINTER IPP ADD + POPUP PRINTER/RELOAD/NETWORK
--------------------------------------------------------------------------
1) EVERY PRINTER OF THE HUB CAN BE ADDED NOW - NOT JUST ONE. Windows
   refused the SECOND per-printer queue (http://<hub-ip>:9235/ipp/
   print/<printer>) because mDNS advertised ONE shared UUID TXT record
   for every queue - each per-printer service looked like a
   re-announcement of the first. Every advertised queue now carries
   its OWN stable printer-uuid (announce + direct TXT answers), so all
   printers appear and add side by side in Windows and on phones. If a
   queue was half-added before the upgrade, remove it once on the
   device and add it again.
2) THE POPUP IS A CONTROL SURFACE NOW. A PRINTER dropdown (the hub's
   printers + status; picking one makes it the OS default - ONE
   command per real change, NOTHING on popup open/reload, and the hub
   endpoint is idempotent: "already default" answers with zero
   commands - the "cmd runs multiple times" bug is dead). A RELOAD
   button re-reads everything. A NETWORK icon shows at a glance:
   gray = offline, green = hub on this PC, teal pulse = Share Receive
   ON listening on the LAN (tooltip names the address). Share
   Receive's sub-label shows the LAN listen address too.
3) allow_extention_advprint_pro.bat REALLY APPLIES HKLM / HKCU NOW.
   The old script deleted ExtensionInstallForcelist on every run and
   never re-wrote it (the CRX force-install was silently wiped). The
   rewrite writes ALL THREE policies per browser (Chrome, Edge, Brave,
   Vivaldi, Chromium, Opera) with duplicate-skip, has a menu
   [1]=HKLM (auto-UAC) [2]=HKCU (no admin) [3]=BOTH [R]=Remove [0]=
   Exit, accepts scripted args (HKLM|HKCU|BOTH|REMOVE) and takes the
   hub address for LAN deployments.

4) IMPORTANT UPGRADE STEP: the extension is auto-updated FROM THE HUB
   (updates.xml) - after updating the hub, check
   http://127.0.0.1:9235/extension/info : it must show
   "stale": false and version 3.3.4. If it shows "stale": true, re-run
   the installer (or restart the hub once) - the embedded CRX was not
   synced; Chrome then silently updates the extension to 3.3.4.

UPGRADE IN 3 STEPS (from any v3.x)
----------------------------------
1. Close the old hub (tray icon -> Exit) and run the new
   AdvPrint-Pro-Setup-3.3.4.exe - it installs over the old folder and
   keeps config.json, the queue database and your rules.
2. Start AdvPrint Pro. The tray tooltip shows "v3.3.4 - running on
   http://127.0.0.1:9235".
3. Chrome updates the extension by itself from the hub within a minute
   (chrome://extensions -> AdvPrint Pro -> 3.3.4). Linux .deb: sudo
   dpkg -i advprint-pro_3.3.4_all.deb.

QUICK VERIFY (2 minutes)
------------------------
- Console: http://127.0.0.1:9235/ui - LAN Sharing card shows "Hub
  addresses" chips (IPv4 AND IPv6 where available), the RAW row shows
  every bound 9100 socket.
- Invite: LAN card -> "Connect another PC" -> Copy invite link -> open
  it on the OTHER PC. The page says which PC's hub it adds and probes
  that PC's own hub first. Open it on the hub PC itself and you get
  the "this invite is for the OTHER PC" explainer - never a self-add.
- Per-printer queues: http://127.0.0.1:9235/printers lists
  ipp://<ip>:9235/ipp/print/<printer> for EVERY printer, Unicode
  names included. Add one on another PC - it connects first try.
- IPv6: on an IPv6-capable PC, netstat -ano | findstr ":9100" shows
  0.0.0.0/your-IPv4 AND [::] rows - both answer.
