WHAT'S NEW IN 2.6.7 (PRINT RELIABILITY - THE TWO "NOTHING PRINTS" BUGS)
  0. TWO REAL PRINT FAILURES ARE FIXED (found through the Debug tab on
     a live install - thank you for the report):
     a. "save-as-PDF failed: [Errno 13] Permission denied" - right
        after the hub writes the PDF, a real-time antivirus / search
        indexer / sync filter briefly holds the fresh file EXCLUSIVELY.
        The save-as-PDF step read the file exactly once, hit the lock
        window and the job died with no retry. The hub now retry-reads
        with backoff (~4 s), writes atomically (.part + rename) and
        probe-reads every file BEFORE a backend (SumatraPDF / lp) is
        started - so the same lock cannot kill the print either.
     b. "print backend exit 1: " on a job for File (PDF) - "File (PDF)"
        was missing from the hub's virtual-printer list, so a QUEUED
        job for it was handed to SumatraPDF as a Windows printer name
        that does not exist (exit 1, no message, dead letter). It now
        routes to the save path - the PDF lands in Downloads\AdvPrint
        with status "saved" - also when Queue Mode is OFF.
  1. BETTER ERROR MESSAGES: the backend's stdout is captured too
     (SumatraPDF reports on stdout, stderr is often empty), and the hub
     pre-checks the printer name - you now get
     "printer 'X' not found on this PC (installed: ...)" instead of a
     silent exit code.
  2. DEBUG TAB: a Windows service stuck in "start pending" (a stale
     state from an old service process - the hub runs from the Startup
     app) is now listed in Problems with the one-line fix.
  NOTHING ELSE CHANGED: full v2.6.4 feature set kept 1:1.
