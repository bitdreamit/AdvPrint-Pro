QUICK NOTE ON v3.5.2 - DASHBOARD DATA YOU CAN TRUST (+ history tools)
----------------------------------------------------------------------
v3.5.1 made every dashboard card live; this release fixes what was
still not honest in the KPI row, kills an annoying browser prompt and
upgrades the History tab. No print, rule, queue, theme or network
logic was touched:

1) REAL SUCCESS RATE - the math used to count only status='printed'
   as success, so a hub that delivers most jobs as saved files sat
   frozen on a printed/failed ratio (your "always 33.3%"). Now:
   - success = printed + saved (a saved file IS a delivered document);
   - failed = failed + dead; canceled jobs stay out of the math
     (canceling is YOUR action, not a printer outcome);
   - the Success Rate tile shows the counts BEHIND the percentage:
     "7d 14 ok / 2 fail" plus a hover tooltip with the full breakdown
     (printed + saved = ok, failed/dead, canceled not counted).
   The number still comes live from your job database on every poll -
   but now it moves when your printing moves and it always explains
   itself.

2) NO MORE "SAVE PASSWORD?" PROMPTS - the Connections tab token boxes
   were type="password" fields, so the browser paired every text box
   on the page with them: typing in the history SEARCH box made
   Chrome offer to save the search text as a password (with the hub
   token as the password half). The token boxes are now ordinary text
   inputs masked by CSS (-webkit-text-security), the real token is
   filled in automatically, and every input on the page is
   autocomplete=off - no browser will ever offer to save anything.

3) DATE + TIME EVERYWHERE - History rows, the dashboard Recent Jobs
   list, the Audit (visitor) rows, the LAN visitors' first/last hit,
   DropZone activity and /debug problem rows used to show the TIME
   only ("14:19:41"), so yesterday's jobs looked like today's. All of
   them show the full "YYYY-MM-DD HH:MM:SS" now.

4) HISTORY: VIEW FILE + DATE FILTER:
   - every history row that still has its stored file gets a
     per-row "View" button next to Reprint - it opens the file INLINE
     in the browser (PDF viewer) via /jobs/<id>/file?view=1, no
     download prompt;
   - a DATE-WISE filter (From / To dates + Clear) queries the WHOLE
     job database server-side (/jobs?date_from=&date_to=), not just
     the last 100 rows - print again that one job from last Tuesday.

5) EVERYTHING ELSE IS THE WORKING v3.5.1 BUILD: the live dashboard
   cards (uptime / service / LAN / IPP / RAW / DropZone / Connections
   / token / real default printer), the ProTheme theme engine (8
   themes + density / corners / frame), the rules table fit fix and
   the single port for every queue.

UPGRADE IN 3 STEPS (from any v3.x)
----------------------------------
1. Close the old hub (tray icon -> Exit) and run the new
   AdvPrint-Pro-Setup-3.5.2.exe - it installs over the old folder and
   keeps config.json, the queue database and your rules.
2. Start AdvPrint Pro. The tray tooltip shows "v3.5.2 - running on
   http://127.0.0.1:9235".
3. Chrome updates the extension by itself from the hub within a minute
   (chrome://extensions -> AdvPrint Pro -> 3.5.2). Linux .deb: sudo
   dpkg -i advprint-pro_3.5.2_all.deb.
