QUICK NOTE ON v3.5.0 - PRO THEMES + DASHBOARD DATA VIEW FIXES
--------------------------------------------------------------
v3.5.0 is a layout + theming release built ON TOP of the working
v3.4.8.1 tree (the rules-table fit stays locked by tests). No print,
rule-matching, queue or network logic was touched. What is new:

1) PRO THEME ENGINE IN THE ONE UI. The console gets 7 color themes -
   Cobalt (new default), Classic IDM (the original v3.2.1 blue lives
   on), Emerald, Violet, Graphite, Midnight and Carbon (the last two
   are full dark themes) - plus light/dark, three densities, two
   corner styles and a framed/borderless window option. Set it from
   the Theme menu in the menu bar or Settings > Appearance; the choice
   is saved in the browser (localStorage key "advprintTheme") and is
   applied BEFORE first paint, so the console never flashes the wrong
   theme. Icon-only sidebar/toolbar items show their label as a
   tooltip on hover/focus/tap.

2) DASHBOARD DATA VIEW NOW AGREES WITH THE REST OF THE UI. The
   glance rows on the dashboard rendered wrong before: the "IPP
   printer" row showed mDNS discovery text instead of its own state,
   mDNS / RAW port / DropZone rows showed static placeholders, the
   Printers-Ready stat counted an idle printer as down ("2/4 - 2
   offline" while the Printers tab said 3 usable) and In Queue showed
   "4 (+2)" - counting the held jobs twice. Fixed: IPP printer shows
   READY + the /ipp/print endpoint, mDNS / RAW / DropZone render
   live, idle printers count as usable, held jobs appear once (in
   the corner label), and progress bars carry rounded widths.

3) LOCAL QR GENERATOR. The QR tiles (hub / invite / IPP) render
   without asking the hub, so they appear even while the hub is
   restarting.

4) THE v3.4.8.1 RULES TABLE FIT STAYS. Every ONE UI table still sits
   in its .tbl-wrap: no column and no Edit button can ever render
   outside the card. tests/test_v348.py still locks it; the rule
   editor keeps the reverted (working) v3.4.7 kind handling - the
   theme work did NOT re-introduce the buggy kind remapping.

UPGRADE IN 3 STEPS (from any v3.x)
----------------------------------
1. Close the old hub (tray icon -> Exit) and run the new
   AdvPrint-Pro-Setup-3.5.0.exe - it installs over the old folder and
   keeps config.json, the queue database and your rules.
2. Start AdvPrint Pro. The tray tooltip shows "v3.5.0 - running on
   http://127.0.0.1:9235".
3. Chrome updates the extension by itself from the hub within a minute
   (chrome://extensions -> AdvPrint Pro -> 3.5.0). Linux .deb: sudo
   dpkg -i advprint-pro_3.5.0_all.deb.

QUICK VERIFY (2 minutes)
------------------------
- Console: http://127.0.0.1:9235/ui - open the Theme menu (top left,
  next to File) and switch Cobalt -> Midnight -> Carbon: the whole
  ONE UI re-colors instantly. Settings > Appearance shows the 8-tile
  picker (7 themes + System) with density / corners / frame options
  and "Reset appearance".
- Dashboard: the IPP printer row shows "READY /ipp/print", RAW port
  shows LISTENING with the address, and the Printers stat matches the
  Printers tab (idle = usable).
- Rules tab: with Paper + Page content set the table fits and the
  Edit button is INSIDE the card (the v3.4.8 fix, still).
- The ONE UI About panel, footer and the tray tooltip say v3.5.0.
- http://127.0.0.1:9235/health reports "version": "3.5.0".
- http://127.0.0.1:9235/extension/info shows "stale": false and
  version 3.5.0 (if stale, restart the hub once).
