QUICK NOTE ON v3.3.1 - THE LAN PC + WINDOWS IPP CONNECTION RELEASE
==================================================================

This release fixes the four reports from the two-PC lab:

1. WINDOWS NOW CONNECTS: adding ipp://<hub>:9235/ipp/print or
   ipp://<hub>:9235/ipp/print/<printer> from another PC failed with
   "Windows couldn't connect to the printer". The hub's IPP answer was
   missing the uri-security-supported attribute and carried fewer
   authentication values than printer URIs - Microsoft's strict IPP
   Class Driver refuses such printers. Fixed (RFC 8011 parallel triple).

2. PER-PRINTER QUEUES WORK INSTANTLY: ipp://<hub>:9235/ipp/print/<name>
   no longer 404s in the first seconds after the hub starts.

3. THE LAN PC CARD IS REAL: Connections > "Another PC (LAN PC)" now
   actually saves the other PC (URL + token -> Connect), shows the live
   CONNECTED/OFFLINE chip and Clear really clears. It no longer rewrites
   the URL field with your own PC's address.

4. SHARE SEND MODE WORKS: flip the new switch in the LAN PC card and
   EVERY print job goes to that PC. If that PC is offline the job is
   HELD (nothing prints locally behind your back) - Print now overrides.

HOW TO UPDATE (5 minutes)
=========================
1. Windows: run AdvPrint-Pro-Setup-3.3.1.exe - it installs over the
   old folder and keeps your printers, history and token.
2. Start AdvPrint Pro. The tray tooltip shows "v3.3.1 - running on
   http://127.0.0.1:9235".
3. Reload the extension: chrome://extensions -> AdvPrint Pro -> the
   reload icon. Check the popup shows "stale": false and version 3.3.1.
   Linux .deb: sudo dpkg -i advprint-pro_3.3.1_all.deb.

CONNECT TWO PCs IN 60 SECONDS
=============================
On the PC that should PRINT (the client):
- Open the console (http://127.0.0.1:9235/ui) -> Connections.
- In "Another PC (LAN PC)" enter the OTHER PC's hub URL
  (http://192.168.1.101:9235) and ITS token, press Connect.
- Flip "Share Send Mode" ON - every job now prints on that PC.
On the PC that RECEIVES (the hub PC): LAN Sharing must be ON
(LAN Sharing card > Enable). The one-click invite link
(http://<hub-ip>:9235/connect?t=<token>) also configures the client PC
automatically when opened there.

WHAT TO CHECK FIRST (30 seconds)
================================
- http://127.0.0.1:9235/health must show "ok": true, "stale": false and
  version 3.3.1. If it shows "stale": true, re-run
  scripts/embed_console.py - the UI in the hub is older than
  console.html; Chrome then silently updates the extension to 3.3.1.
