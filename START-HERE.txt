QUICK NOTE ON v3.5.8 - REAL WINDOW BUTTONS + BRAND + TAB MEMORY

console itself:

   tab stat card.

   writes ?path=history (etc.) into the URL AND saves the last tab.
   Refresh or re-open lands on the SAME tab: the URL path wins,
   otherwise the saved tab, otherwise the Dashboard.
4. NO UUID ON THE DASHBOARD - the uuid-looking machine id that sat
   next to "Dashboard" (and in the old title bar) is gone for good.
5. CMD/POWERSHELL STILL 100% SILENT - the v3.5.7 SILENT WINDOWS
   guarantee is untouched: CREATE_NO_WINDOW on every helper the hub
   launches, zero flicker; UAC prompts are the only thing that
   ever shows (they must be approved).
6. v3.5.7 / v3.5.6 FEATURES ALL PRESENT - LAN admin console
   (ui_admin_mode + admin_ips), ipp:// printer URLs, signed CRX
   chain, windowless hub + tray icon, full build kit.

QUICK NOTE ON v3.5.7 - SILENT WINDOWS (NO CMD FLASHES)
------------------------------------------------------
v3.5.6 made the console adminable from the whole network. v3.5.7
fixes the last cosmetic Windows annoyance - flashing CMD windows:

1. NO MORE CMD WINDOW FLASHES - the hub runs windowless, but its
   reg.exe policy calls, the elevated service PowerShell and the
   CUPS lp fallback each popped their own console window. First run
   + every console policy poll could flash 10-25 windows. Every
   helper now launches with CREATE_NO_WINDOW - nothing shows.
2. UAC PROMPTS STILL APPEAR - when something genuinely needs admin
   approval (firewall rule, service install, CRX policy pass) the
   Windows UAC prompt still shows; that one must be approved, it is
   not a bug.
3. NOTHING ELSE CHANGED - same windowless hub + tray icon, same
   hub.log, same print chain; macOS/Linux behaviour is unchanged
   (the hide flag is 0 there). A new build-gate test sweeps the
   source so a future console flash cannot silently return.
4. v3.5.6 FEATURES ALL PRESENT - LAN admin console (ui_admin_mode +
   admin_ips), ipp:// printer URLs, signed CRX chain, full build kit.

QUICK NOTE ON v3.5.6 - LAN ADMIN CONSOLE + IPP:// PRINTER URLS
--------------------------------------------------------------
v3.5.5 made the tree self-building. v3.5.6 makes the hub easier to
CONTROL and friendlier to Android:

1. CONSOLE ADMIN FROM ANY DEVICE ON YOUR NETWORK - the ONE UI now
   answers on the hub PC's own network by default (ui_admin_mode=lan).
   The admin centre PC 192.168.1.2 keeps 127.0.0.1 + 192.168.1.2, and
   a PC or phone on any other IP of the SAME network opens the same
   console at http://192.168.1.2:9235/ui. Modes: self (the old
   v3.2.6 hub-PC-only lock) / lan (default) / any (everything the
   Allowed-IPs gate lets in). Edit in THE ONE UI > LAN Sharing >
   Console admin access.
2. admin_ips - EXTRA ADMINS FROM ANY NETWORK - exact IP, CIDR or
   wildcard entries (office PC on 10.x, phone on mobile data, VPN
   peer) get full console control in every mode. The hub PC itself is
   ALWAYS an admin (loopback + own IPs auto-added) and an EMPTY list
   never widens the gate. Printing rules (allowed_ips) and console
   rules (ui_admin_mode + admin_ips) are two INDEPENDENT controls.
3. EVERY REMOTE CONSOLE SESSION IS AUDITED - ui.remote_admin rows
   show who controlled the hub from where.
4. PRINTER URLS NOW DISPLAY ipp:// - the standard-port chip, the
   Android add-printer guide and the printer landing page show
   ipp://IP:631/ipp/print (Android's manual-add screen refuses
   http:// - its Save button stays disabled). The hub still SPEAKS
   plain HTTP/IPP; only the displayed scheme changed. Paste ipp://
   or just the IP - Android assumes port 631 + /ipp/print itself.

QUICK NOTE ON v3.5.5 - FULL SOURCE + WINDOWS BUILD KIT
------------------------------------------------------
v3.5.4 made the extension package trustworthy again (CRX signed with
the stable key and Chrome-verified as a build gate). v3.5.5 makes the
whole SOURCE TREE trustworthy and buildable on your own Windows PC:

1. ONE-COMMAND WINDOWS BUILD - double-click build.cmd (or
   python scripts\build-all.py) and get every artifact from source:
   the signed CRX, the extension zip, the Setup EXE and even the
   Linux .deb (built in pure Python - no WSL, no dpkg-deb needed).
   Full step-by-step guide: docs/BUILD-WINDOWS.md.
2. INCOMPLETE-TREE PROTECTION - a missing source file used to fail
   deep inside the installer compiler ("stage/install/hub-stop.ps1
   -> no files found"). The build now checks the complete file list
   FIRST and fails with the exact names of whatever is missing.
3. TWIN-SYNC + NSIS PRE-CHECK - the unix/windows hub copies must be
   byte-identical and every File reference in installer/setup.nsi
   must resolve before the EXE build starts.
4. STALE-VERCHIP FIX - the extension Options page version chip
   (stuck on v3.5.1 since the popup comeback) now shows v3.5.5.

THE CRX IS STILL SIGNED AND VERIFIED: every CRX is packed fresh from
the extension source with the SAME stable release key - the extension
ID is UNCHANGED (likldbkamojokkfdlcjibiljpgbbnohc), so pairing,
settings and the hub auto-update chain all survive. tool/crx3.py
verify (a Chrome-identical signature check) stays a HARD BUILD GATE.
All artifacts carry SHA256 checksums in docs/SHA256SUMS-3.5.5.txt -
check before installing:

  Windows CMD        : certutil -hashfile AdvPrint-Pro.crx SHA256
  Windows PowerShell : Get-FileHash AdvPrint-Pro.crx -Algorithm SHA256
  Linux / macOS      : sha256sum AdvPrint-Pro.crx

EVERYTHING ELSE IS THE WORKING v3.5.4 BUILD: the always-visible status
bar, the real success rate, no more save-password prompts, date+time
everywhere, the history per-row View file button and date filter, the
live dashboard cards, the ProTheme theme engine (8 themes + density /
corners / frame) and the single port for every queue.

UPGRADE IN 3 STEPS (from any v3.x)
----------------------------------
1. Close the old hub (tray icon -> Exit) and run the new
   AdvPrint-Pro-Setup-3.5.5.exe - it installs over the old folder and
   keeps config.json, the queue database and your rules.
2. Start AdvPrint Pro. The tray tooltip shows "v3.5.5 - running on
   http://127.0.0.1:9235".
3. Chrome updates the extension by itself from the hub within a minute
   (chrome://extensions -> AdvPrint Pro -> 3.5.5). Linux .deb: sudo
   dpkg -i advprint-pro_3.5.5_all.deb.
   Drag-install instead? Use the included AdvPrint-Pro.crx ( Developer
   mode ON at chrome://extensions ) - its signature is build-verified.
