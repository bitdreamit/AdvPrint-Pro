  LD_LIBRARY_PATH=$HOME/nsis-root/usr/lib/x86_64-linux-gnu \

3Set up the CENTER PC (the one printing PC)

  1. Install the tool: run AdvPrint-Pro-Setup-3.1.2.exe (Windows) or sudo dpkg -i advprint-pro_3.1.2_all.deb (Linux). The hub starts at http://127.0.0.1:9235 (tray icon / systemd user service).
  2. Open THE ONE UI: tray menu → Console (THE ONE UI), or START-CONSOLE.vbs, or a browser on http://127.0.0.1:9235/ui?token=<token>. The native window opens the same page (pywebview → Qt → GTK → Chrome app window → browser ladder — no PySide6, installer ≈10 MB).
  3. Console → Settings tab: turn LAN sharing ON (or tray → Allow LAN in firewall). Keep Per-printer IPP queues ON and mDNS ON. Save & Apply.
  4. Console → Extension tab: copy the token — child PCs need it.
  5. Verify: Console → Printers shows every printer with its own ipp://…:9235/ipp/print/<printer> queue; press Test page.
Firewall (Windows): inbound TCP 9235 (printing) + UDP 5353 (mDNS discovery). The Setup EXE adds both; tray → "Allow LAN in firewall" re-adds TCP any time.

4Set up the CHILD PCs (extension and/or IPP — no tool)

Way A — extension only (silent browser printing with rules)

  1. Install the extension on the child PC: load AdvPrint-Pro.crx / the zip (chrome://extensions → Developer mode → Load unpacked), or let the center PC's force-install policy install it silently (domain PCs).
  2. Extension → Options → Connections → Center PC / child PC mode:
    • Mode: Auto (recommended) — uses a local tool when present, otherwise the Center PC. Choose Center PC only for a pure child PC.
    • Center PC hub URL: http://CENTER-IP:9235
    • Center PC token: the token from step 4 above → Save settings.
  3. The status line proves it: [auto] local tool NOT running → printing on CENTER PC: http://…. Popup → Console opens the center's THE ONE UI.

Way B — per-printer IPP queues (no extension at all)

  1. Windows 10/11: Settings → Printers → Add device — the center's printers appear by themselves (mDNS). Or Add manually → "Select a shared printer by name" → ipp://CENTER-IP:9235/ipp/print/<printer>.
  2. Linux/CUPS: lpadmin -p advprint-hp -E -v ipp://CENTER-IP:9235/ipp/print/HP-Laser-103-107-108 -m everywhere
  3. macOS / iPhone / Android: discovered automatically (Bonjour / AirPrint / Mopria).
  4. Queue names accept the raw Windows name (URL-encoded) or the slug form — both work. The Console → IPP Printer tab lists every URL with a Copy button.
Both ways combined is fine: extension for silent browser printing + rules, IPP queues so ANY application on the child PC prints on the center PC too. Many child PCs can connect to one center PC at the same time. Full details: docs/CENTER-CHILD-PCS.md.

  2. GitHub → Releases → Draft a new release → choose tag v3.1.2.

7Troubleshooting

SymptomCause → Fix
Child PC cannot reach the hubLAN sharing OFF → Console → Settings → LAN sharing ON, restart; firewall → tray "Allow LAN in firewall"; wrong token → copy from Console → Extension.
Printer not discovered on phonesmDNS OFF or firewall UDP 5353 → Settings → mDNS ON; the center must be ON the same LAN (no VPN).
IPP queue unknown (404)Typo in the queue name — copy the exact URL from Console → IPP Printer. Names are case/punctuation-insensitive.
Console shows offline cardHub not running → start AdvPrint Pro (tray / START-CONSOLE.vbs); extension Console tab → Retry now.
Native window falls back to browserNo GUI backend found — pip install pywebview for the WebView2/WebKit window (the ladder also uses an existing Chrome/Edge automatically).
makensis not foundUse the local-prefix recipe in §2.4, or sudo apt-get install nsis.
Extension still shows old versionForce-installed from the hub → restart Chrome; manual install → chrome://extensions → Update.
