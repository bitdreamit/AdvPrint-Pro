Power switches

Every silent / background behavior of AdvPrint Pro - one switch each, plain English.

AdvPrint enabled (master switch)

OFF = the extension stops completely: no printing, no auto-print, no window.print() hook, no page API, no context menu. A gray OFF badge shows on the toolbar icon. Use it when you want the browser to behave 100% natively without uninstalling AdvPrint.

Queue mode (jobs wait in order)

ON = every job goes through the hub queue in order (Pause/Resume in the popup or hub works, big jobs line up). OFF = instant print - each job is handed straight to the printer the moment it arrives (hub sends queue:false), nothing waits behind earlier jobs, Pause has no effect. If no printer is active (offline / paper-out / error) the job is auto-queued instead of failing and prints when the printer is back.

Auto-print rules (silent background printing)

The power switch for every rule in the Rules tab - the same switch that sits on the Rule Manager bar (v3.0.6: the popup no longer carries it; it lives here). ON = armed rules fire hiddenly when their URL or page content matches, each job on its rule's printer, copies and paper. OFF (paused) = NO rule auto-prints; manual prints (popup buttons, right-click menu) keep working - exactly like the queue Pause, but for rules.

Intercept window.print() (web app prints go silent)

Web apps (Odoo, POS, dashboards) that call window.print() are printed silently through the hub instead of opening the dialog. Also intercepts Ctrl+P / Cmd+P. This is the same switch that used to sit in the popup (moved to Options in v3.0.2) - one setting: hookPrint.

Debug mode - find problems fast

ON = this extension reports every error it hits (network failures, rejected token, print-call exceptions, jobs that ended failed/dead) to the hub, and the hub logs verbosely. Open the Debug tab (or the dashboard Debug card, or /debug) to see WHEN / WHY / WHERE printing fails - no guessing. Turn off again when everything works.

Retry when the hub comes back

If the hub is offline, jobs are kept in the browser and sent automatically as soon as the hub answers again (checked every minute).

Browser behavior

What happens around the printing - tabs, menus, the toolbar icon.

Print every PDF opened in the browser (simple mode)

ANY PDF you open - any site, any URL - is printed silently and its tab closes. No print view, no dialog, no rules needed. Turn off to auto-print only URLs matching your rules (Rules tab).

Close tab after auto-print (default OFF)

OFF (default): auto-printed URLs keep their tab open like a normal page. ON: when a rule auto-prints an opened URL, the tab is closed right after the job is queued - zero browser view, the paper just comes out. You opt in; AdvPrint never closes tabs on its own by default.

When a page print call fails

Controls the automatic fallback of printPdfLink() / printPdf() on web pages: if the hub cannot print a PDF (hub off, printer error, not a PDF), either open the URL in a normal tab so the browser prints it the default way, or stay completely silent. A per-call opts.fallback (true/false) in page JS overrides this setting.

Right-click menu

Adds "AdvPrint Pro" to the right-click menu: print page / print selection / print linked PDF / print screenshot.

Toolbar badge (green OK / red !)

Shows OK or ! on the extension icon for a few seconds after every job, so you see it worked without opening anything.

This PC (Self PC) - the main hub

The hub + printers on THIS computer. Used when Share Send Mode is OFF (default).

Start the hub with python advprint.py serve, or use the installed "AdvPrint Pro" shortcut / "AdvPrint Tool" menu. New installs get a private random token - read it with python advprint.py token or in the hub dashboard. Old installs keep the pre-2.0 default token until changed (the hub will warn you). Detect token fills the current token automatically from the running hub (one-click fix - also offered on the dashboard error page itself).

Center PC / child PC mode (v3.1.2) - many PCs, ONE printing PC

This child PC needs NO AdvPrint tool: the extension prints through the Center PC's hub (or its per-printer IPP queues). The tool on THIS PC is used automatically whenever it is installed and running.

Child PC setup in 3 steps: 1) install this extension, 2) put the Center PC's URL + token here, 3) done - or add its printers directly as IPP queues (ipp://CENTER-IP:9235/ipp/print/<printer>, announced by mDNS). All existing features (queue mode, rules, LAN profile, history) keep working against whichever hub is active.

Another PC (LAN PC) - print over the network

A SECOND hub profile. Put the OTHER PC's hub URL + its token here; turning Share Send Mode ON in the popup sends every print job to that PC. OFF (default) prints on the Self PC above.

On the OTHER PC: enable Share Receive Mode (its popup or the LAN sharing block below = share_lan), restart its hub and allow TCP 9235 through the firewall once. Copy its token there (dashboard or python advprint.py token). Your own PC does NOT need Share Receive ON to send - receiving is the OTHER PC's switch.

LAN sharing - let other PCs print through this one

The hub listens on 127.0.0.1 only until you switch this on. Other PCs must use your token - wrong tokens get locked out.

Queue & retries

Hold jobs while the printer reports offline

Jobs wait (status "held") until the printer is ready again - nothing is lost. Turn off if your printer always reports offline but still prints (misreported status).

Instant print fallback to queue

Queue mode OFF + printer not active: the job is auto-queued instead of failing, and prints when the printer is back.

Security

Strict token mode (header only)

ON = mutating calls (POST) must send the token in the X-AdvPrint-Token header (the extension does this anyway). OFF = token in the URL/body is also accepted (1.x compatibility).

Never lock out this PC (127.0.0.1)

ALWAYS ON since v2.6.4 - this is now built into the hub, so it can no longer be switched off: a stale token in one Chrome window can never lock out your own dashboard, tray and extension.

Developer API - window.advprint

    
Available on every page (when the hook is enabled). All methods return Promises.


<script>
  await window.advprint.status();            // hub health
  await window.advprint.printers();          // [{name, is_default, status}]
  await window.advprint.printPage({title});  // print current page
  await window.advprint.printPdf(url, {title, printer});
  await window.advprint.print({
    title: 'Receipt 12', printer: '', copies: 1,
    priority: 1,                    // v2.0: urgent first
    pages: '1-3,5',                 // v2.0: range - v2.2: odd/even too
    per_sheet: 2,                   // v2.1: n-up
    quality: 'draft',               // v2.2: draft|normal|high|'600dpi'
    dpi: 600,                       // v2.2: explicit DPI
    scale_pct: 150, margin_mm: 8,   // v2.1: rendered jobs
    duplex: 'duplex',               // two-sided
    paper_size: 'A4', orientation: 'landscape',
    profile: 'Invoice',             // v2.0: hub print profile
    text: '|center|HELLO|',         // or:
    lang: 'escpos',                 // v2.0: raw ESC/POS or ZPL
    html: '<h1>Invoice</h1>',      // or:
    pdfBase64: 'JVBERi0...',       // or:
    pdfUrl: 'https://.../report.pdf'
  });
</script>


    
Direct HTTP also works from any language:
      POST http://127.0.0.1:9235/print with header
      X-AdvPrint-Token - add "queue": false
      for immediate printing. New in v2.0: priority, pages,
      profile, run_at, lang, reason, watermark - see docs/API.md.
