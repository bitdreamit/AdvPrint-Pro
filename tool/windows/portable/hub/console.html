Auto-Print Rules

the multi-printer control center · hidden silent printing, fully managed
📚 How you set which rule for which 3 steps, one dialog — press New rule or Edit on any row
1. Match by — URL / address filter (Chrome match pattern, e.g. *://www.htncr.org/lab/*), optional page content (text the page must contain, e.g. ZPL or Patient Report) and URL type (any / PDF link / web page / plain text). All conditions must pass. 2. Then print — pick the printer, what to print (whole page, linked PDF, raw stream, selected element), copies and paper. 3. When — On enables the rule, Auto prints silently without any dialog; optional schedule (e.g. evenings only). Rules run top to bottom — first match wins, drag rows to re-order. Every firing is logged in the activity log below.

Syntax = Chrome match patterns: scheme://host/path with * wildcards (* = any scheme, *.host = subdomains, trailing * = any path). Power Switches

every silent / background behavior of the extension — one switch each, managed from here
⚡ Power switches same switches as the extension options — now in the ONE UI
AdvPrint enabled (master switch)

OFF = the extension stops completely: no printing, no auto-print, no window.print() hook, no page API, no context menu. A gray OFF badge shows on the toolbar icon.

Queue mode (jobs wait in order)

ON = every job goes through the hub queue in order (Pause/Resume works, big jobs line up). OFF = instant print. If no printer is active the job is auto-queued instead of failing.

Auto-print rules (silent background printing)

The power switch for every rule in the Rules tab. OFF (paused) = NO rule auto-prints; manual prints keep working.

Intercept window.print() (web app prints go silent)

Web apps (Odoo, POS, dashboards) that call window.print() print silently through the hub instead of opening the dialog. Also intercepts Ctrl+P / Cmd+P.

Debug mode — find problems fast

ON = the extension reports every error to the hub and the hub logs verbosely. Open the Debug tab to see WHEN / WHY / WHERE printing fails.

Retry when the hub comes back

If the hub is offline, jobs are kept in the browser and sent automatically as soon as the hub answers again (checked every minute).

UI language

English or বাংগ্লা for the popup and the extension pages. "Automatic" follows the browser language.

These switches live in the paired browsers. Press Save & push to browsers and every paired Chrome/Edge gets the new settings within a minute — no need to open the extension options page anymore.

⚠ Chrome message: "This extension is not listed in the Chrome Web Store and may have been added without your knowledge" expected — explained
⚠ This extension is not listed in the Chrome Web Store and may have been added without your knowledge.
What it means: the browser shows this banner for any extension installed outside the Web Store — your own AdvPrint-Pro.crx deployed by policy or drag & drop. It is not a virus warning and printing is not affected.
Why you see it: AdvPrint Pro is a private, self-hosted extension for this organisation — it is intentionally not on the Web Store. The banner disappears when a Web Store listing is published.
What to do: nothing — keep it, or make the banner vanish by installing the CRX through the policy table above (policy-installed extensions show as "Installed by your administrator" instead of the warning). Check chrome://extensions — the extension ID must match the forcelist value above.
